## What's Planned for v0.2.0

### 1️⃣ HNSW Vector Indexes (Weeks 1-3)
**Problem**: IVFFlat is slow for production (100-200ms per query)  
**Solution**: HNSW hierarchical graph indexing  
**Result**: 4-10x faster (20-50ms), better accuracy

**Changes**:
- PostgreSQL HNSW indexing (requires pgvector 0.5.0+)
- Configurable parameters (m, efConstruction, ef)
- Benchmarks: 140ms → 35ms latency
- Tuning guide for different use cases
- Migration script from IVFFlat
- Backward compatible (IVFFlat deprecated but supported)

---

### 2️⃣ Multi-Database Support (Weeks 3-5)
**Problem**: Locked into PostgreSQL only  
**Solution**: Abstract storage adapter pattern  
**Result**: Support PostgreSQL + Qdrant in v0.2.0, Weaviate/OpenSearch in v0.2.1

**Architecture Changes**:
- SearchAdapter interface (contracts package)
- PgVectorAdapter implements interface
- New QdrantAdapter (Qdrant database support)
- Factory pattern for easy adapter selection
- Zero API changes to RetrievalOps core

**Qdrant Integration**:
```typescript
const adapter = new QdrantAdapter({
  url: "http://localhost:6333",
  collectionName: "tickets"
});
```

**Future**: Weaviate, OpenSearch, Elasticsearch (v0.2.1+)

---

### 3️⃣ Query Optimization (Weeks 6-7)
**Problem**: Queries are static; no synonym expansion, no negation  
**Solution**: Preprocessing + synonym expansion pipeline  
**Result**: +20-30% better recall on complex queries

**Features**:
- Query cleaning (normalize spaces, case)
- Synonym expansion ("payment" → "transaction")
- Negation extraction ("NOT timeout" → filter)
- Intent detection ("why" → root_cause)
- Field hints ("in errorMessage:" → boost)

**Example**:
```
Input: "why did payment fail NOT timeout?"
↓
Output: {
  cleaned: "did payment fail",
  expanded: ["payment failure", "transaction error"],
  negations: ["timeout"],
  intent: "root_cause"
}
↓
Search: Run multiple expanded queries, merge, filter negations, boost hints
↓
Result: Better matches because synonyms expanded
```
