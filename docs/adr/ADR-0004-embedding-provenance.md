# ADR-0004: Embedding Provenance Tracking

**Status**: Accepted  
**Date**: 2026-08-09  
**Author**: RetrievalOps Core Team

## Context

Embeddings are not data; they are **model outputs**. An embedding generated by `sentence-transformers/all-MiniLM-L6-v2` is meaningless when used to search against vectors generated by `OpenAI/text-embedding-3-small`.

Production systems need to:
1. Know which model generated each embedding
2. Prevent mixing embeddings from different models
3. Support model migrations (reindex with new model)
4. Track when embeddings were created

## Decision

**Require complete provenance tracking in all indexed vectors.**

## Provenance Record

Every indexed vector must include:

```ts
interface EmbeddingProvenance {
  embeddingModel: string;        // Model identifier (e.g., "Xenova/all-MiniLM-L6-v2")
  embeddingVersion: string;      // Model version (e.g., "2.6.0")
  dimensions: number;            // Vector dimensions (e.g., 384)
  distanceMetric: "cosine" | "dot" | "euclidean";  // Similarity metric
  sourceUpdatedAt: Date;         // When source document was last updated
  embeddedAt: Date;              // When embedding was created
  contentHash: string;           // SHA-256 of source text
}
```

## Implementation

### At Index Time

```ts
await retrieval.index({
  entity: document,
  document: {
    id: "doc-1",
    content: "Hello world"
  },
  provenance: {
    model: "Xenova/all-MiniLM-L6-v2",
    version: "2.6.0"
  }
});
```

RetrievalOps captures:
1. Embedding model and version (from provider metadata)
2. Dimensions (validated against model metadata)
3. Distance metric (from model capability)
4. Content hash (SHA-256 of text)
5. Timestamps (now and source update time)

### Model Mismatch Detection

At search time:

```ts
const result = await retrieval.search({
  entity: document,
  query: "Hello"
});
```

RetrievalOps verifies:
1. Query embedding uses same model as stored vectors
2. Dimensions match
3. Distance metric is compatible

If mismatch: **Error with clear message**

```
ModelMismatchError: Query uses OpenAI/text-embedding-3-small (1536D)
but index contains Xenova/all-MiniLM-L6-v2 (384D) embeddings.
Reindex or use matching embedding provider.
```

## Consequences

### Prevents Silent Failures
Without provenance, a model switch produces silently wrong results (no error, just garbage rankings).

With provenance, the system fails loudly:
```
error: Cannot search with different embedding model
```

### Enables Safe Migrations

```ts
// Phase 1: Index with new model in parallel
await retrieval.index(doc, { model: "new-model" });

// Phase 2: Shadow-execute searches with new model
const shadowResult = await retrieval.search(query, { shadow: true });

// Phase 3: Compare results; if good, cutover
// Phase 4: Cleanup old indexes
```

### Storage Overhead

Each vector record stores ~256 bytes of metadata:
- Model name/version
- Metrics
- Timestamps
- Hash

For 1M documents: ~256 MB overhead (acceptable).

## Alternatives Considered

### No provenance tracking
- **Pro**: Minimal storage
- **Con**: Silent failures; model switches are bugs

### Model versioning via separate field
- **Pro**: Simpler schema
- **Con**: Joins required; consistency hard to enforce

### Automatic model detection
- **Pro**: No manual tracking
- **Con**: Fails if model produces identical dimensions (e.g., two 384D models)
